8. OPTIMISATION / CRASHS (Java 64 + 32 bits)
   - CAUSE DE CRASH CORRIGEE : quand Android tue le moteur de rendu des WebView (manque de memoire, tres
     frequent sur les telephones Android 11 / 32 bits), TOUTE l'appli est fermee si une seule WebView ne
     gere pas "onRenderProcessGone". Le HUD le gerait, mais PAS les dialogues (DialogManager), l'ecran de
     chargement (LoadingScreen) ni le launcher (MainActivity) -> c'est corrige pour les 3.
     Les dialogues repassent en natif, l'ecran de chargement se ferme, le launcher se recree.
   - Etat du joueur vers le HUD : le moteur l'envoie deja 10 fois/s (main.cpp). Le Java ajoute un plafond
     de 15/s (filet de securite, le dernier etat n'est jamais perdu) et, depuis la v19b, des valeurs arrondies :
     a l'arret le meme etat n'est plus renvoye a la WebView (correction : la v19 disait "30 a 60 fois/s", c'etait faux).
   - L'ecran de chargement libere sa page (images + musique) pendant le jeu.
   - Minimap : 30 images/s max au lieu de 40 ; ombres couteuses des jauges coupees.
   - C++ (samp + samp32, jniutil.cpp) : verification d'exception JNI ajoutee aux 3 appels qui n'en avaient pas.
   - Pour les crashs qui restent : envoie le logcat (ou le fichier log du jeu) au moment du crash,
     surtout les lignes "FATAL", "SIGSEGV", "backtrace" : je pourrai viser la cause exacte.
